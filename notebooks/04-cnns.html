Convolutional Neural Networks¶

Why MLPs fail on images, what convolutions actually do, and how to read what a trained CNN has learned.

This tutorial walks through CNNs in three movements:

  1. Why we need CNNs at all — what breaks when you flatten a 32 × 32 image into a 3 072-element vector and hand it to an MLP.
  2. The convolution operation — kernels, strides, padding, pooling. The math is small; the inductive bias is enormous.
  3. A trained CNN, opened up — visualising the learned filters and the feature maps they produce. CNNs are easier to interpret than the modern ML literature suggests.

The runnable notebook uses sklearn's tiny load_digits dataset (1 797 hand-written digits, 8 × 8 grayscale) so it finishes in under a minute on CPU. The tutorial page itself supplements that with CIFAR-10 figures that were pre-rendered locally — colour images make the filter-visualisation lesson land harder.

3. Why MLPs struggle with images — flattening¶

An MLP requires a 1-D input. So before you can feed an image to one, you must flatten it from [H, W] (or [C, H, W]) into a single long vector. Doing so destroys the spatial information that makes an image an image:

  • Pixels that were neighbours (say, two pixels on the cat's whisker) end up far apart in the flattened vector.
  • The model has no way to know that "row 5, column 7" is next to "row 5, column 8". It has to learn spatial structure from scratch.
  • Translating the cat 3 pixels to the right produces a completely different input vector — even though the content is the same.

4. The other MLP problem — parameter explosion¶

For an MLP, the first hidden layer has

parameters = input_features × hidden_neurons + hidden_neurons

For our toy 8 × 8 digits with a 64-neuron hidden layer that's 64 × 64 + 64 = 4 160 parameters. Manageable.

For CIFAR-10 (32 × 32 × 3) with the same 64 neurons: 3 072 × 64 + 64 = 196 672. Already 47× bigger.

For ImageNet (224 × 224 × 3) with a 512-neuron first hidden layer: 150 528 × 512 + 512 = 77 070 848 parameters — just in the first layer. Untrainable on most hardware. This is what the field calls parameter explosion.

CNNs sidestep both problems with one trick: weight sharing. The same small kernel is applied at every position in the image.

5. The convolution operation¶

A 2-D convolution is a local weighted sum:

$$ \text{output}(i, j) = \sum_m \sum_n \text{input}(i + m, j + n) \cdot \text{kernel}(m, n) $$

In words:

  1. Pick a small kernel (e.g. 3 × 3) of learnable weights.
  2. Place it on the top-left of the input.
  3. Multiply each kernel weight by the underlying input pixel; sum the 9 results. That single number becomes one output pixel.
  4. Slide the kernel one step right; repeat. Slide one step down at the end of each row.

The output is a 2-D feature map that lights up wherever the input looks like the kernel. PyTorch's nn.Conv2d does all of this for you; the only thing you tune is the kernel size, the number of output channels (how many different kernels), the stride (step size), and padding (how many zero-pixels to add around the input).

The output-size formula¶

A general 2-D convolution with kernel size $k$, padding $p$, and stride $s$ applied to an input of side $n$ produces an output of side

$$ n_{\text{out}} = \left\lfloor \frac{n + 2p - k}{s} \right\rfloor + 1 $$

Memorise this — you will use it every time you sketch a CNN architecture. Try the three cases below in your head before running the cell.

In [4]:
for n, k, p, s in [(32, 3, 1, 1),   # 'same' convolution
                   (32, 3, 0, 1),   # 'valid' convolution, no pad
                   (32, 3, 0, 2)]:  # stride 2 → downsample
    n_out = (n + 2*p - k) // s + 1
    print(f'  n={n}  k={k}  pad={p}  stride={s}  -> output side {n_out}')

  n=32  k=3  pad=1  stride=1  -> output side 32
  n=32  k=3  pad=0  stride=1  -> output side 30
  n=32  k=3  pad=0  stride=2  -> output side 15

6. Pooling — controlled downsampling¶

After each convolution, we typically halve the spatial dimensions with a pooling layer. Two flavours:

  • Max pooling (F.max_pool2d): take the maximum of each 2 × 2 patch. Keeps the strongest activation, discards the rest. Default for CNNs.
  • Average pooling (F.avg_pool2d): take the average. Smoother; useful at the very end of a network as a "global pool".

Both reduce the feature map by a factor of stride in each dimension, which means fewer parameters in the next layer and a wider receptive field for any neuron downstream (the patch of the original image that ultimately influences it).

7. Building the CNN¶

The template that has dominated computer vision since the 1990s is

[Conv → ReLU → Pool] × N → Flatten → FC → softmax

For our 8 × 8 digits we'll use a small two-block version:

input 1×8×8
  → Conv 3×3, 1→8 channels, padding 1   (preserves 8×8)
  → ReLU
  → MaxPool 2×2                          (halves to 4×4)
  → Conv 3×3, 8→16 channels, padding 1   (preserves 4×4)
  → ReLU
  → AdaptiveAvgPool to 4×4               (no-op here, defensive)
  → Flatten → 256
  → FC 256 → 32 → ReLU → 32 → 10
In [6]:
class DigitsCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(1, 8, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(8, 16, kernel_size=3, padding=1)
        self.fc1   = nn.Linear(16 * 4 * 4, 32)
        self.fc2   = nn.Linear(32, 10)
    def forward(self, x):
        x = F.relu(self.conv1(x))
        x = F.max_pool2d(x, 2)
        x = F.relu(self.conv2(x))
        x = F.adaptive_avg_pool2d(x, 4)
        x = x.flatten(1)
        x = F.relu(self.fc1(x))
        return self.fc2(x)

model = DigitsCNN()
print(model)
print('\ntotal parameters:', sum(p.numel() for p in model.parameters()))

DigitsCNN(
  (conv1): Conv2d(1, 8, kernel_size=(3, 3), stride=(1, 1), padding=(1, 1))
  (conv2): Conv2d(8, 16, kernel_size=(3, 3), stride=(1, 1), padding=(1, 1))
  (fc1): Linear(in_features=256, out_features=32, bias=True)
  (fc2): Linear(in_features=32, out_features=10, bias=True)
)

8. Train it¶

Same loop you wrote in tutorial 03 — the only thing that changed is the model class. CrossEntropyLoss includes softmax, so the model outputs logits (raw, unnormalised scores).

In [7]:
opt = optim.Adam(model.parameters(), lr=3e-3)
loss_fn = nn.CrossEntropyLoss()
tr_loss, va_acc = [], []
for ep in range(60):
    model.train()
    loss = loss_fn(model(Xtr_t), ytr_t)
    opt.zero_grad(); loss.backward(); opt.step()
    tr_loss.append(loss.item())
    model.eval()
    with torch.no_grad():
        va_acc.append((model(Xte_t).argmax(1) == yte_t).float().mean().item())
print(f'final test accuracy: {va_acc[-1]:.3f}')

fig, axL = plt.subplots(figsize=(6.4, 3.0))
axL.plot(tr_loss, color='#1f77b4', lw=1.6, label='train loss')
axL.set_xlabel('epoch'); axL.set_ylabel('cross-entropy', color='#1f77b4')
axL.tick_params(axis='y', labelcolor='#1f77b4')
axR = axL.twinx()
axR.plot(va_acc, color='#2ca02c', lw=1.6); axR.set_ylim(0, 1.02)
axR.set_ylabel('test accuracy', color='#2ca02c')
axR.tick_params(axis='y', labelcolor='#2ca02c')

9. Open it up — look at the learned filters¶

CNNs are interpretable when they are small. Each 3 × 3 filter in conv1 becomes an edge / blob detector at some orientation. The same observation, in cat visual cortex experiments, motivated CNNs in the first place (Hubel & Wiesel, 1962).

12. What changes for real images¶

This whole notebook lives in the easy regime: 8 × 8 grayscale, 10 classes, 1 800 samples. The tutorial page accompanying this notebook embeds CIFAR-10 versions of every plot — colour images, 32 × 32, 50 000 training samples — and a quantitative MLP-vs-CNN comparison that makes parameter explosion concrete.

Everything you'd add for real datasets is more of the same:

  • More conv blocks (depth) → larger receptive field per output neuron
  • Batch normalisation between conv and ReLU → training stability
  • Data augmentation in a DataLoader → translation/rotation invariance
  • A DataLoader itself, with batches > 1, instead of feeding the whole set at once
  • Fine-tune a pretrained backbone (ResNet, EfficientNet, ViT) — this is how 95 % of modern vision projects actually work, not training from scratch

What you've built¶

  • A 2-block CNN that hits > 98 % on 8 × 8 digits in 60 s on CPU.
  • The output-size formula every CNN sketch depends on.
  • Visualisations of the learned filters and the feature maps they produce — interpretability as a free side effect.
  • The vocabulary (kernel, stride, padding, pooling, receptive field, feature map) that applies to every CNN you'll meet, from LeNet to EfficientNet.
