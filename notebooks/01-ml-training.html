Machine learning training, from scratch¶

The training loop, by hand. Loss curves, train/val splits, overfitting, and the three regularisation knobs that fix it — built from a single neuron upward.

This tutorial is about what loss.backward() actually does. We start by hand-deriving the gradient for a one-parameter regression, watch gradient descent walk down a loss curve in NumPy, then rewrite the same thing in PyTorch using autograd. After that we get clinical: a train / val split, a model deliberately too big, and three knobs (early stopping, L2 weight decay, dropout) compared head-to-head.

1. The loss landscape¶

For a model ŷ = w·x + b with MSE loss, the loss is a function of w and b. Fix b and plot loss against w: it's a parabola. The minimum is the best slope; gradient descent's job is to slide down to it.

In [1]:
import numpy as np, torch, torch.nn as nn, torch.optim as optim
import matplotlib.pyplot as plt
torch.manual_seed(0); np.random.seed(0)

# A toy regression: y = 1.5 x + 0.4 + noise
N = 80
x_data = np.linspace(-3, 3, N)
y_data = 1.5 * x_data + 0.4 + 0.4 * np.random.randn(N)

# Sweep w with b fixed; plot the MSE
ws = np.linspace(-1, 4, 200)
losses = [((w * x_data + 0.4 - y_data) ** 2).mean() for w in ws]
plt.figure(figsize=(6.5, 3.2))
plt.plot(ws, losses); plt.axvline(ws[np.argmin(losses)], color='red', ls='--')
plt.xlabel('w'); plt.ylabel('MSE'); plt.title('Loss surface (1-D slice)')
plt.tight_layout(); plt.show()

2. Hand-derive the gradient¶

For one data point $(x_i, y_i)$ and prediction $\hat{y}_i = w x_i + b$, the squared error is $L_i = (\hat{y}_i - y_i)^2$. The chain rule gives

$$\quad \frac{\partial L_i}{\partial w} = 2(\hat{y}_i - y_i)\,x_i, \qquad \frac{\partial L_i}{\partial b} = 2(\hat{y}_i - y_i).$$

Averaged across the batch, we get the gradient of the total MSE.

In [2]:
def gradient_descent_step(x, y, w, b, lr=0.01):
    y_pred = w * x + b
    err    = y_pred - y                # (N,)
    grad_w = 2 * np.mean(err * x)      # ∂L/∂w
    grad_b = 2 * np.mean(err)          # ∂L/∂b
    return w - lr * grad_w, b - lr * grad_b

w, b = 0.0, 0.0
history = []
for ep in range(200):
    w, b = gradient_descent_step(x_data, y_data, w, b)
    loss = ((w * x_data + b - y_data) ** 2).mean()
    history.append(loss)

print(f'learned w = {w:.4f}  (true 1.5)')
print(f'learned b = {b:.4f}  (true 0.4)')
print(f'final MSE = {history[-1]:.4f}')

learned w = 1.4220  (true 1.5)
learned b = 0.3810  (true 0.4)
final MSE = 0.1433

3. The same training loop in PyTorch¶

PyTorch's autograd computes the gradient for you, no matter how complex the model. The five lines of the inner loop — forward → loss → zero → backward → step — are the same for every PyTorch model in this series.

In [3]:
x_t = torch.tensor(x_data, dtype=torch.float32).view(-1, 1)
y_t = torch.tensor(y_data, dtype=torch.float32).view(-1, 1)

model = nn.Linear(1, 1)              # `Wx + b`, learnable W and b
opt = optim.SGD(model.parameters(), lr=0.01)
loss_fn = nn.MSELoss()
for ep in range(200):
    y_pred = model(x_t)              # forward
    loss = loss_fn(y_pred, y_t)      # how wrong
    opt.zero_grad()                  # reset gradients
    loss.backward()                  # autograd computes ∂L/∂w, ∂L/∂b
    opt.step()                       # w ← w − lr·∂L/∂w

print(f'learned W = {model.weight.item():.4f}   B = {model.bias.item():.4f}')

learned W = 1.4220   B = 0.3904

4. A harder problem — a noisy sine¶

The linear model above is too rigid for anything curvy. Switch to a small MLP and the same training loop fits sin(x).

In [4]:
X = torch.linspace(-torch.pi, torch.pi, 100).view(-1, 1)
y = torch.sin(X) + 0.15 * torch.randn_like(X)

idx = torch.randperm(100)
tr, va = idx[:70], idx[70:]
Xt, yt = X[tr], y[tr]
Xv, yv = X[va], y[va]

plt.figure(figsize=(6, 3.0))

plt.legend(frameon=False); plt.xlabel('x'); plt.ylabel('y')

5. A deliberately too-big network¶

Give a 5-hidden-layer, 128-unit-wide MLP a tiny noisy dataset and you will see classic overfitting. The training loss falls all the way; the validation loss bottoms out then climbs.

In [5]:
class MLP(nn.Module):
    def __init__(self, hidden=128, depth=5, p_drop=0.0):
        super().__init__()
        layers = [nn.Linear(1, hidden), nn.Tanh()]
        for _ in range(depth - 1):
            layers += [nn.Linear(hidden, hidden), nn.Tanh()]
            if p_drop > 0:
                layers.append(nn.Dropout(p_drop))
        layers.append(nn.Linear(hidden, 1))
        self.net = nn.Sequential(*layers)
    def forward(self, x): return self.net(x)

def train(model, Xt, yt, Xv, yv, epochs=3000, lr=0.01, wd=0.0):
    opt = optim.Adam(model.parameters(), lr=lr, weight_decay=wd)
    fn = nn.MSELoss(); tr_h, va_h = [], []
    for ep in range(epochs):
        model.train()
        L = fn(model(Xt), yt); opt.zero_grad(); L.backward(); opt.step()
        tr_h.append(L.item())
        model.eval()
        with torch.no_grad():
            va_h.append(fn(model(Xv), yv).item())
    return tr_h, va_h

tr_o, va_o = train(MLP(128, 5), Xt, yt, Xv, yv)
print(f'final train MSE {tr_o[-1]:.4f}   val MSE {va_o[-1]:.4f}')

final train MSE 0.0057   val MSE 0.0267

6. Reading a loss curve¶

Train loss alone is a lie. A model whose training loss falls to zero might be memorising the noise. The validation loss is the only honest readout. The point where val loss starts climbing is the right moment to stop training — that is early stopping.

In [6]:
best_ep = int(np.argmin(va_o))
fig, ax = plt.subplots(figsize=(6.5, 3.4))
ax.plot(tr_o, label='train', lw=1.5)
ax.plot(va_o, label='val',   lw=1.5)
ax.axvline(best_ep, color='gray', ls='--', lw=1)
ax.text(best_ep+30, max(va_o)*0.65, f'early-stop @ ep {best_ep}', color='gray', fontsize=9)
ax.set_yscale('log'); ax.set_xlabel('epoch'); ax.set_ylabel('MSE (log)')
ax.set_title('Overfitting: val loss climbs while train loss falls')
ax.legend(frameon=False); plt.tight_layout(); plt.show()

7. Three knobs that fix overfitting¶

knob what it does when to reach for it
early stopping Stop when val loss stops improving Always — free
L2 / weight decay Penalise large weights in the loss function When val plateaus high
dropout Randomly zero activations during training Deeper nets, larger data

A fourth knob — reduce model capacity — is the most underused. If your model still overfits with the others on, try a smaller network.

In [7]:
tr_r, va_r = train(MLP(128, 5), Xt, yt, Xv, yv, wd=1e-3)
tr_d, va_d = train(MLP(128, 5, p_drop=0.1), Xt, yt, Xv, yv)

fig, ax = plt.subplots(figsize=(7, 3.4))
ax.plot(va_o, label='no reg',      lw=1.5)
ax.plot(va_r, label='L2 (1e-3)',   lw=1.5)
ax.plot(va_d, label='dropout 0.1', lw=1.5)
ax.axvline(best_ep, color='gray', ls='--', lw=1, label='early-stop point')
ax.set_yscale('log'); ax.set_xlabel('epoch'); ax.set_ylabel('val MSE (log)')
ax.set_title('Three regularisers on the same model and data')
ax.legend(frameon=False); plt.tight_layout(); plt.show()

8. Save and load — for any model¶

Every PyTorch model can be persisted in two lines. Save the state_dict, not the model object — that decouples the weights from the code, so loading still works if you refactor the model class later.

In [8]:
# save
torch.save(MLP(128, 5).state_dict(), '/tmp/model.pt')

# load (you re-instantiate the same architecture, then fill in weights)
m_loaded = MLP(128, 5)
m_loaded.load_state_dict(torch.load('/tmp/model.pt'))
m_loaded.eval()  # important — turns off dropout, batch-norm running averages
print('loaded model with', sum(p.numel() for p in m_loaded.parameters()), 'parameters')

loaded model with 66433 parameters
